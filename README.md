# האפליקציה של ליה — deployment guide

Installable PWA. No backend, no accounts, no network required after first load.
All data (progress, settings, personal words, voice recordings) lives in IndexedDB
on the device, with JSON export/import for backup.

## Contents

```
lia-app/
├── index.html          the entire app
├── manifest.json       PWA manifest (name, icons, shortcuts, portrait lock)
├── sw.js               service worker — precaches the shell, cache-first
├── icons/              192, 512, 512-maskable, apple-touch (180), favicon
└── splash/             iOS launch images, 5 device sizes
```

## 1. Deploy (required — the app needs HTTPS)

Opening `index.html` from the filesystem will **not** work properly:
service workers, microphone access and speech recognition all require a
secure context. Localhost counts as secure; `file://` does not.

**Netlify Drop** — drag the `lia-app` folder onto https://app.netlify.com/drop.
Done in a minute, free, HTTPS included.

**GitHub Pages** — push the folder contents to a repo, then
Settings → Pages → Deploy from branch → `main` / root.

**Local testing** — `cd lia-app && python3 -m http.server 8000`,
then open http://localhost:8000

## 2. Install on a device

- **Android/Chrome** — a native install prompt appears; or menu ⋮ → Add to Home screen
- **iOS/Safari** — Share ⬆️ → Add to Home Screen (iOS never shows an automatic prompt)

Launch from the home-screen icon, not the browser, to get the standalone window
and the splash screen.

## 3. What works where

| Feature | Android/Chrome | iOS/Safari |
|---|---|---|
| Offline, install, icons, splash | ✅ | ✅ |
| Text-to-speech (Hebrew) | ✅ | ✅ (needs a Hebrew voice installed) |
| Voice recording | ✅ webm/opus | ✅ mp4/aac (format auto-detected) |
| Speech recognition ("תגידי את זה", "הצנצנת") | ✅ | ❌ not implemented in Safari |
| Wake lock (screen stays on) | ✅ | ⚠️ partial |

The two speech-recognition games degrade gracefully: "הצנצנת" still opens with a
tap, and "תגידי את זה" shows an explanation instead of breaking.

## 4. Backup

Parent screen (long-press 👤 → solve the sum) → ⚙️ הגדרות → גיבוי ושחזור.
Export writes one JSON file containing everything, recordings included.
**Do this after any recording session** — the device is the only copy.

## 5. Optional: real app-store builds

### Android — Play Store via TWA
```bash
npm i -g @bubblewrap/cli
bubblewrap init --manifest https://YOUR-URL/manifest.json
bubblewrap build          # produces a signed .aab
```

### iOS — App Store via Capacitor
```bash
npm init -y && npm i @capacitor/core @capacitor/cli
npx cap init "Lia Words" com.yourname.liawords --web-dir=.
npx cap add ios && npx cap sync && npx cap open ios
```
Requires a Mac, Xcode, and an Apple Developer account ($99/yr).
Apple rejects thin web wrappers (guideline 4.2) — the offline mode, microphone
recording and local storage are the native-value story to lead with.

### Kids category (both stores)
- Privacy policy URL is mandatory
- No third-party analytics, no ads, no external links
- Google Play Data Safety form: declare **no data collected, no data shared** —
  which is literally true here, since nothing leaves the device

## 6. Art & store assets

```
store/
├── play/           5 screenshots, 1080x1920, captioned
├── appstore/       5 screenshots, 1290x2796 (6.7")
└── feature-graphic-1024x500.png
tools/
├── make_assets.py  app icons + iOS splash screens
├── make_art.py     כּוֹכִי the mascot (5 expressions) + category patterns
└── make_store.py   store screenshots, captured from the running app
```

The mascot and category patterns are inline SVG generated by `make_art.py`;
re-run it and paste the output over the generated-art block at the top of the
script in `index.html`. Store screenshots are captured from the real app rather
than mocked, so they can never drift from what ships:

```bash
python3 tools/make_store.py
```

## 7. Tests & CI

The Playwright suite covers layout on four screen sizes, every category and game
opening, four games played to completion, IndexedDB persistence, backup
export/restore, and the PWA (manifest, icons, service worker, offline).

```bash
pip install playwright && python -m playwright install chromium
python3 -m http.server 8000 &
BASE_URL=http://localhost:8000 python3 tests/test_suite.py
```

`.github/workflows/test-and-deploy.yml` runs it on every push and pull request.
On `main`, a passing run deploys to GitHub Pages and rewrites the service worker
cache version to the commit SHA, so returning devices always get the new build.

To enable: Settings → Pages → Source → **GitHub Actions** (not "deploy from branch").

## 8. Updating

Bump `VERSION` in `sw.js` (e.g. `lia-v1` → `lia-v2`) whenever you redeploy.
Old caches are purged on activation, and the app shows a "new version" toast
on the next launch.
